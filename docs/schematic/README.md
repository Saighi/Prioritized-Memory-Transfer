# Network schematic — four backends, one figure

A "paper-minimal" wiring diagram of the two-population predictive-coding network
(teacher **T** above student **S**; value neurons, the three error populations, the
recurrent weights, and the labelled prediction/drive couplings). The same figure is
generated four ways so you can pick the toolchain you actually want to live with.

Blue = top-down prediction, orange = bottom-up / drive. `ε_TS = x_S − x_T`.

## Single source of truth

[`spec.py`](spec.py) declares the nodes, edges, and labels once (no torch dependency).
Every backend imports `build_spec()`, so the figure is identical across tools and
parametrized from one place:

- The teacher's interface drive is the **signed** precision `π_ST`. `build_spec(phase="sleep")`
  shows it as a *reversed* (negative) precision `π_ST<0` (drive-to-disagree); `phase="wake"`
  shows the ordinary `π_ST>0` (recall). The sign *is* the phase — no separate gate. Each
  renderer takes `--phase`.
- Pass a `ModelConfig`-like object as `values=` to fold numeric gains into the labels
  (e.g. `π_ST=-0.21`); the paper-minimal default keeps them symbolic.

> **Note:** the committed rendered artifacts (`*.svg/.png/.pdf`, `tikz/network.tex`,
> `d2/network.d2`) were regenerated by hand-editing the drive label to `π_ST<0`; re-run the
> render scripts for a clean rebuild.

## The four backends

| Backend | Render here? | Command | Output |
|---|---|---|---|
| **schemdraw** (Python) | ✅ rendered | `python schemdraw_fig.py` | `schemdraw_sleep.svg` / `.png` |
| **TikZ** (LaTeX) | ✅ rendered | `python tikz/render.py` | `tikz/network.pdf` / `.svg` |
| **D2** (CLI) | source only* | `python d2/render.py` | `d2/network.d2` (→ `.svg` w/ CLI) |
| **Penrose** | source only** | see `penrose/README.md` | `penrose/network.svg` |

\* D2 CLI not installed here — `network.d2` is generated; `winget install terrastruct.d2`
then re-run, or paste into https://play.d2lang.com.
\*\* Penrose needs a Node toolchain; the trio is a verified-in-editor starter (run at
https://penrose.cmu.edu/try). See [`penrose/README.md`](penrose/README.md).

All Python entry points run in the `pytorch` conda env (`jinja2`, `schemdraw`,
`matplotlib` are the only deps; `schemdraw` was `pip install`ed).

## How they compare

| | schemdraw | TikZ + Jinja2 | D2 | Penrose |
|---|---|---|---|---|
| **Aesthetics** | clean, rounded | publication-grade | clean, modern | beautiful (with effort) |
| **Install** | `pip install schemdraw` | LaTeX (MiKTeX/TeXLive) | one CLI binary | Node toolchain |
| **Stays in your workflow** | ✅ pure Python / notebooks | ✗ separate compile | ✗ external CLI | ✗ external |
| **Layout control** | explicit (you place) | explicit (you place) | **auto** (fights fixed shape) | **optimizer** (indirect) |
| **Math labels** | mathtext (`$…$`) | full LaTeX ✅ | plain unicode only | LaTeX ✅ |
| **Effort to first clean figure** | low | low–medium | low | **high** |
| **Best when** | iterate in-repo, notebooks | the paper figure | quick connectivity sketch | reusable math-diagram system |

## Recommendation

Your topology is **fixed** (always T, S, three error populations), so auto-layout tools
(D2, Penrose) are working against you — you spend effort *pinning down* a layout they
want to choose. The two explicit-placement backends won:

- **schemdraw** for day-to-day: pure Python, renders inline in your `#%%` notebooks, no
  external toolchain. Promote `schemdraw_fig.build()` to `src/viz_schematic.py` and it
  sits alongside `viz_static` / `viz_interactive`.
- **TikZ** for the actual paper figure: it's how PC papers (Bogacz, Friston, Tang) draw
  these, and `tikz/network.svg`/`.pdf` is already publication-ready.

D2 is a fine 30-second connectivity sketch; Penrose is only worth it if you want a
reusable declarative math-diagram setup beyond this one figure.
